Так, цей проєкт можна розгорнути за тією самою логікою, але він буде **більш дослідницьким**, ніж токенізатор: основний результат — не просто оброблений текст, а **формальний стильовий профіль твору**, побудований на наборі кількісних характеристик.

# Курсова робота

## «Програмний засіб для автоматизованого літературного та стилістичного аналізу художніх текстів»

### 1. Мета проєкту

Розробити програмний засіб для автоматизованого кількісного аналізу художніх текстів, який дозволяє досліджувати їхні лексичні, синтаксичні та статистичні характеристики, формувати на їх основі профіль стилю та порівнювати між собою різні твори або авторів.

Загальна схема роботи:

```text
Художній текст
      │
      ▼
Попередня обробка
      │
      ▼
Токенізація
      │
      ▼
Лематизація
      │
      ├──────────────┐
      ▼              ▼
Лексичний       Синтаксичний
аналіз          аналіз
      │              │
      └──────┬───────┘
             ▼
      Статистичний аналіз
             │
             ▼
      Профіль стилю
             │
       ┌─────┴─────┐
       ▼           ▼
   Порівняння    Звіт
    текстів
```

---

# 2. Основна ідея

Програма повинна перетворювати художній текст не просто на набір слів, а на **набір вимірюваних характеристик**.

Наприклад, для твору:

```text
Кількість слів:                 152340
Унікальних слів:                 21350
Лексичне різноманіття:            0.140
Середня довжина слова:             5.8
Середня довжина речення:          18.4
Максимальна довжина речення:     127
Частка прикметників:              0.091
Частка дієслів:                   0.132
Частка іменників:                 0.241
Повторюваність фраз:              0.037
```

У результаті отримується вектор характеристик:

$$
S(T)=(x_1,x_2,\ldots,x_n)
$$

який можна розглядати як **стильовий профіль тексту**.

---

# 3. Вхідні дані

Програма повинна працювати з одним або декількома текстами.

Наприклад:

```text
texts/
    author1/
        novel1.txt
        novel2.txt

    author2/
        novel1.txt
        novel2.txt
```

Для кожного тексту необхідно зберігати метадані:

```text
Text
 ├── title
 ├── author
 ├── year
 ├── language
 └── content
```

Це дозволить надалі порівнювати:

* два твори;
* твори одного автора;
* різних авторів;
* твори різних періодів творчості.

---

# 4. Попередня обробка

Перший етап — очищення та нормалізація тексту.

Необхідно передбачити:

* видалення зайвих пробілів;
* нормалізацію перенесень рядків;
* обробку лапок;
* обробку тире та дефісів;
* нормалізацію Unicode;
* видалення службових символів;
* збереження або видалення пунктуації;
* приведення регістру.

Наприклад:

```text
  Це   був
дуже  дивний   день...
```

перетворюється на:

```text
Це був дуже дивний день...
```

При цьому бажано **не знищувати оригінальний текст**, оскільки пунктуація та форматування можуть бути важливими для стилістичного аналізу.

---

# 5. Токенізація

Наступний етап — розбиття тексту на токени.

Наприклад:

```text
"Це був дуже дивний день."
```

→

```text
Це
був
дуже
дивний
день
.
```

Для кожного токена бажано зберігати:

```text
Token
 ├── text
 ├── normalizedText
 ├── position
 ├── sentenceNumber
 ├── type
 └── lemma
```

Типи:

```text
WORD
NUMBER
PUNCTUATION
SPECIAL
```

---

# 6. Лематизація

Лематизація дозволяє звести різні словоформи до базової форми.

Наприклад:

```text
будинок
будинку
будинком
будинки
будинків
```

→

```text
будинок
```

Аналогічно:

```text
йшов
йде
йти
йшли
```

можуть бути зведені до відповідної леми.

Це дозволяє розрізняти:

**кількість словоформ**

та

**кількість різних лем.**

Це дуже важливо для оцінювання лексичного багатства.

> Якщо курсова виконується для української мови, лематизацію краще реалізувати через відповідний NLP-інструмент або морфологічний словник, а не намагатися повністю створити морфологічний аналізатор з нуля.

---

# 7. Лексичний аналіз

Необхідно визначити основні характеристики словникового складу твору.

## 7.1. Загальна кількість слів

$$
N=\text{кількість токенів типу WORD}
$$

Наприклад:

```text
Words: 152340
```

---

## 7.2. Кількість унікальних слів

$$
V=|\{w_1,w_2,\ldots,w_N\}|
$$

Наприклад:

```text
Total words:       152340
Unique words:       21350
```

Аналогічно необхідно розрахувати кількість **унікальних лем**.

---

# 8. Лексичне різноманіття

Базовий показник:

$$
TTR=\frac{V}{N}
$$

де:

* \(V\) — кількість унікальних слів;
* \(N\) — загальна кількість слів.

Наприклад:

$$
TTR=\frac{21350}{152340}\approx0.140
$$

Чим більша величина, тим більша частка різних лексем у тексті.

Але для великих текстів простий TTR має недолік: він сильно залежить від довжини тексту. Тому як розширення можна реалізувати:

* Root TTR;
* Corrected TTR;
* MATTR;
* Yule's K.

Це дасть значно цікавішу дослідницьку частину.

---

# 9. Частотний аналіз

Програма повинна будувати таблицю частот:

| Слово  | Частота |
| ------ | ------: |
| і      |   15432 |
| в      |    8321 |
| бути   |    4210 |
| людина |    1240 |
| день   |    1175 |

Необхідно передбачити:

* сортування за частотою;
* пошук найчастотніших слів;
* відображення top-N;
* фільтрацію stop words.

Наприклад:

```text
Top 20 content words
```

дозволить отримати більш змістовну характеристику тексту.

---

# 10. Частини мови

Якщо використовується морфологічний аналізатор, кожному слову можна призначити POS-tag:

```text
NOUN
VERB
ADJ
ADV
PRON
PREP
CONJ
...
```

Тоді для твору можна отримати:

```text
Nouns:       24.1 %
Verbs:       13.2 %
Adjectives:   9.1 %
Adverbs:      6.4 %
Pronouns:    11.7 %
```

Це вже є важливою характеристикою стилю.

Наприклад, можна досліджувати:

$$
P_{noun}=\frac{N_{noun}}{N}
$$

$$
P_{verb}=\frac{N_{verb}}{N}
$$

тощо.

---

# 11. Аналіз речень

Необхідно визначити межі речень.

Для кожного речення бажано зберігати:

```text
Sentence
 ├── number
 ├── text
 ├── tokenCount
 ├── wordCount
 ├── punctuationCount
 └── ...
```

На основі цього розрахувати:

* кількість речень;
* середню довжину речення;
* медіанну довжину;
* мінімальну довжину;
* максимальну довжину;
* стандартне відхилення;
* розподіл довжин.

Наприклад:

```text
Average sentence length: 18.4 words
Median:                  15
Minimum:                  1
Maximum:                127
Std deviation:           12.7
```

---

# 12. Розподіл довжин речень

Це вже цікавий елемент стилістичного аналізу.

Необхідно побудувати гістограму:

```text
Number of sentences
│
│              ███
│          ████████
│       █████████████
│    █████████████████
│ █████████████████████
└──────────────────────────
   1  10  20  30  40  50
       words per sentence
```

Порівнюючи два автори, можна побачити різний характер синтаксису.

---

# 13. Аналіз пунктуації

Необхідно визначити частоту:

```text
.
,
!
?
:
;
—
–
(
)
"
...
```

Наприклад:

```text
Comma:       18230
Dash:         4210
Exclamation:   830
Question:      1240
Ellipsis:       512
```

Також можна визначати співвідношення:

$$
P_{comma}=\frac{N_{comma}}{N_{sentences}}
$$

і аналогічні характеристики.

---

# 14. Повторюваність слів

Необхідно дослідити повторення.

Наприклад:

```text
людина ... людина ... людина
```

Програма повинна визначати:

* частоту слів;
* повторення в сусідніх реченнях;
* повторення через \(k\) слів;
* повторення на початку речень.

Можна ввести параметр:

```text
windowSize = 20
```

і перевіряти, які слова повторюються в межах вікна.

---

# 15. Повторюваність фраз

Це одна з найцікавіших алгоритмічних задач.

Необхідно реалізувати пошук:

* біграм;
* триграм;
* \(n\)-грам.

Наприклад:

```text
біграми:
"в цей"
"цей день"
"на нього"

триграми:
"в цей день"
"не міг зрозуміти"
```

Для кожної \(n\)-грами визначається частота.

Наприклад:

| Phrase              | Frequency |
| ------------------- | --------: |
| `в цей день`        |        23 |
| `не міг`            |        18 |
| `на наступний день` |        15 |

---

# 16. Алгоритмічна частина пошуку повторів

Для пошуку повторюваних фраз можна використати кілька підходів:

### Простий

Перебір усіх \(n\)-грам:

$$
O(N)
$$

для фіксованого \(n\).

### Hash-based

Використання:

```text
unordered_map<ngram, frequency>
```

### Розширений

Для пошуку довших повторюваних фрагментів можна використати:

* rolling hash;
* suffix array;
* suffix tree.

Для курсового достатньо hash-based алгоритму, а складніші структури можна запропонувати як додаткове завдання.

---

# 17. Характерні мовні конструкції

Програма повинна дозволяти шукати задані шаблони.

Наприклад:

```text
"якщо ... то ..."
"не тільки ... а й ..."
"так ... як ..."
```

або конструкції на основі POS:

```text
ADJ + NOUN
```

тобто:

```text
зелений ліс
великий будинок
темна ніч
```

Таким чином система може визначати типові граматичні конструкції автора.

# 19. Порівняння текстів

Це повинно бути окремою функцією програми.

Наприклад:

```text
Text A
vs.
Text B
```

Порівнюються:

| Характеристика  | Автор A | Автор B |
| --------------- | ------: | ------: |
| Words           |  152340 |  128430 |
| TTR             |   0.140 |   0.182 |
| Avg word length |     5.8 |     6.2 |
| Avg sentence    |    18.4 |    24.1 |
| Nouns           |   24.1% |   21.3% |
| Verbs           |   13.2% |   15.7% |
| Adjectives      |    9.1% |   12.4% |

При цьому програма **не повинна сама робити літературознавчий висновок**, що один стиль «кращий» або «гірший». Вона повинна показувати вимірювані характеристики та їх відмінності.

---

# 20. Відстань між стилями

Для більш сильної курсової можна представити стиль як вектор:

$$
S=(x_1,x_2,\ldots,x_n)
$$

і розраховувати відстань між двома текстами.

Наприклад, евклідова відстань:

$$
d(A,B)=
\sqrt{\sum_{i=1}^{n}(A_i-B_i)^2}
$$

Перед цим характеристики потрібно нормалізувати.

Альтернативно:

* Manhattan distance;
* cosine distance.

Це дозволяє математично формалізувати **ступінь подібності статистичних профілів**.

# 28. Кластеризація текстів — сильне розширення

Для сильної курсової можна зробити ще один крок.

Кожен текст представляється вектором:

$$
S_i=(x_1,x_2,\ldots,x_n)
$$

Потім використовується, наприклад, **k-means**.

```text
             Style space

       ● ●
     ● ● ●              Author A

                       ○ ○
                     ○ ○ ○       Author B

          ▲ ▲
        ▲ ▲ ▲                   Author C
```

Програма може показувати, які тексти мають близькі статистичні характеристики.

Важливо: це буде **кластеризація за вибраними статистичними ознаками**, а не автоматичне встановлення авторства.

---

# 29. Аналіз авторства — додатковий рівень

Ще складніший варіант — побудувати систему, яка за характеристиками тексту намагається визначити автора серед заданого набору кандидатів.

Наприклад:

```text
Unknown text
       │
       ▼
Style vector
       │
       ▼
Classifier
       │
       ├── Author A
       ├── Author B
       └── Author C
```

Для курсового це можна зробити як експериментальне розширення з використанням:

* k-NN;
* Naive Bayes;
* logistic regression;
* decision tree.

Але це вже **окремий рівень задачі**, тому в базову версію його включати не обов'язково.

---

# 30. Аналіз складності

Необхідно оцінити складність основних алгоритмів.

Наприклад, для \(N\) токенів:

* токенізація — приблизно \(O(N)\);
* побудова частотного словника — \(O(N)\) у середньому при hash map;
* сортування частот — \(O(V\log V)\);
* побудова \(n\)-грам — \(O(N)\) для фіксованого \(n\);
* порівняння профілів — \(O(K)\), де \(K\) — кількість характеристик.

Це потрібно перевірити експериментально на текстах різного розміру.

* великого документа;
* тексту з великою кількістю пунктуації;

* прямої мови;
* чисел;
* абревіатур;
* дефісів;

* повторюваних фраз;

Окремо необхідно перевірити правильність:

```text

sentence count
frequency
TTR
average sentence length
n-gram frequency
```

### Ключова дослідницька задача курсової

Я б сформулював її так:

> **Дослідити можливість формалізації авторського стилю художнього тексту за допомогою набору лексичних, морфологічних, синтаксичних та статистичних характеристик і розробити програмний засіб для автоматичного обчислення цих характеристик та порівняння стильових профілів текстів.**
